# 合并固件 · 一块板跑两个作品（自动感知版）

一块 EG800Z Duino 同时承载「同桌/凑近」（超声链路）和「AI房评师」（光照链路）。
插上什么传感器，对应链路就自己活；拔掉就自己停。**烧一次固件，现场随便换插法。**

## 识别策略（按传感器特性区分对待，不搞一刀切）

| 传感器 | 判定方式 | 为什么 |
|---|---|---|
| BH1750 | 开机 I2C 扫 0x23，应答即在 | 数字器件，探测 100% 可靠 |
| AHT20 | 开机 I2C 扫 0x38 | 同上；失败只丢温湿度不阻断 |
| KY-018 | ADC 连读 8 次查合理性（不贴边、有微动） | 官方明说悬空引脚读数随机，单次探测不可信 |
| HC-SR04 | **运行期热识别**：连续 8 帧有效回波激活；激活后连续 30 秒全灭才停用 | "没回波"≠"没插"（可能对着吸音物），开机一票否决会误杀 |

主日志会打 `★ 链路激活` / `○ 链路停用`，现场演示时这两行就是讲解词。

## 接线（与两个独立固件完全一致，合并没改引脚）

- HC-SR04：Trig→GPIO30，Echo→GPIO31（**必须 1k/2k 分压**）
- KY-018：AO→A1（ADC1），**必须外接 ≥100k 分压**（默认 100k/100k）
- BH1750 / AHT20：VCC/GND/SDA→I2C0、SCL→I2C0（两个共用一条总线，地址不同）
- RGB r/g/b→32/4/5，蜂鸣→6，心跳灯→7

## 烧录（Windows，流程和原来一样）

1. QPYcom 把 `main.py`、`config.py` 传 `/usr`，`lib/` 整个目录传 `/usr/lib/`
2. 跑 `calib.py`（沿用 firmware-solar 的），结论回填 `config.py` 的
   `SATURATION_MV` / `LIGHT_INVERT`
3. 重启。REPL 看日志：几条 `★/○` 决定本次哪几个链路在跑

## 与两个独立固件的关系

`firmware-solar/` 和 `whatif-lab/firmware/` 原样保留——合并版是运行时的
超集，不是替代。哪个现场出问题可以立刻退回单固件。
`tests/sim_merged.py` 用 fake 传感器验证了四种插法组合（全都没插/只有光/
只有超声/全都在）的激活、停用与并行行为，改动逻辑后先跑它。

## 已知边界

- 光照链路单独激活时 RGB 不亮（灯归链路一），反馈看 8001 页面
- KY-018 与 BH1750 同时插时优先 BH1750，数据口径 lux
- 两条链路两个 MQTT 连接（各自重连互不牵连），Cat.1 流量完全够
- 超声停用后重插需要重新攒 8 帧（约 0.8 秒），演示无感
